# Память предпочтений (MCP `preferences`)

У пользователя есть личный сервис, где хранятся его предпочтения на любые темы: как писать код, каким должен быть
ответ ИИ, привычки в хобби, правила конкретных проектов. Каждое правило — это «люблю» или «не люблю», уровень
(«жёстко» / «по умолчанию» / «вкус»), иногда «почему» и пример «так / не так», папка (например, «Программирование › Код › Не люблю») и иногда жёсткие ограничения вида `file_lines <= 100 lines`.
Сервис — источник правды о вкусах пользователя: учитывай его вместо догадок, и пользователю не придётся повторять
одно и то же в каждом чате.

## Как добраться до сервиса

Проверь по порядку и используй первый доступный способ:

1. **MCP-инструменты** сервера `preferences`. Имена зависят от клиента: в Claude Code —
   `mcp__preferences__get_context_for_task`, в других — `get_context_for_task` у сервера `preferences`
   (иногда `preferences.get_context_for_task`). Если инструменты отложены (deferred), сначала загрузи их поиском
   инструментов по слову `preferences`.
2. **Запасной клиент** `scripts/pm.mjs` из этого навыка — если MCP не подключён, но есть терминал и Node ≥ 18.
   Токен берётся из `PREFERENCES_MCP_TOKEN`, `PREFERENCES_ENV_FILE` (путь к `.env` сервиса) или `./.env`;
   адрес — `PREFERENCES_MCP_URL` (по умолчанию `http://localhost:3000/mcp`):
   ```bash
   node <путь-к-навыку>/scripts/pm.mjs context "напиши PHP-сервис курса валют"
   node <путь-к-навыку>/scripts/pm.mjs search "рыбалка" --domain fishing
   node <путь-к-навыку>/scripts/pm.mjs add "не люблю, когда в коде нет тестов"
   ```
   Все команды — в шапке скрипта (`context`, `search`, `folder`, `folders`, `projects`, `project`, `add`, `main`, `tools`).
3. **Ничего нет** — скажи одной фразой, что память предпочтений не подключена, и предложи подключить
   (`references/connect.md`). Задачу выполняй дальше без неё: не выдумывай, что пользователь любит.

Токен никогда не выводи в ответ, в логи и в файлы проекта.

## 1. В начале задачи — загрузить контекст

Прежде чем писать код, текст или план, вызови `get_context_for_task`:

- `task` — одна-две фразы о задаче с ключевыми словами: язык, фреймворк, тип работы, название проекта, если оно
  звучало. Пример: `"написать PHP-сервис с HTTP-эндпоинтом курса валют"`.
- `applies_to` — не передавай по умолчанию: он сужает выборку до правил с этими метками и может отрезать общие
  правила. Передавай, только когда нужно именно адресное (например, `["php"]`).

Ответ сгруппирован по папкам: `[не люблю · жёстко]` (полярность и уровень), пояснение, `почему`, `так` / `не так`,
`constraints`, `applies_to`, `id`.
Как применять:

- **Блок «Жёсткие ограничения»** — обязательные требования к результату. Оператор уже записан как требование:
  `file_lines <= 100 lines` значит «каждый файл не длиннее 100 строк» — раздели код на модули, если нужно;
  `wake_up_hour >= 5 hour` — «не раньше пяти утра». Перед сдачей результата проверь, что ограничения выполнены
  (например, посчитай строки в файлах).
- **«Не люблю»** — избегай. **«Люблю»** — предпочитай. Насколько строго — говорит уровень:
  - **жёстко** — соблюдай всегда; нарушение — дефект, который надо исправить до сдачи (как ограничение);
  - **по умолчанию** — соблюдай; отступить можно, только если есть причина — назови её пользователю;
  - **вкус** — учитывай, если нет причин поступить иначе; отступление объяснять не нужно.
- **«почему»** объясняет, где правило действительно важно — по нему решай пограничные случаи. **«так» / «не так»** —
  образец: делай как в «так», не как в «не так».
- Правила про другого ассистента (например, `applies_to: chatgpt`) — это вкус пользователя в целом; учитывай их,
  когда они про стиль ответа или работы.
- Если правило противоречит прямой просьбе пользователя в текущем сообщении, побеждает текущая просьба. Скажи
  об этом одной фразой и предложи обновить память.
- Одной строкой сообщи, какие предпочтения учтены: «Учёл: файлы ≤ 100 строк, строгая типизация в PHP». Не
  пересказывай всю память.

Контекст загружается один раз на задачу. Повторно — если тема сменилась (другой проект, язык, домен).

## 2. Пользователь спрашивает о своих предпочтениях

- Про тему или поиск: `get_preferences({ query, domain?, folder?, project?, polarity?, tags? })`. Домены:
  `programming`, `ai_assistants`, `fishing`, `travel`, `food`, `communication`, `project`, `other` (бывают и
  новые). «Что я не люблю» → `polarity: "dislike"`.
- Обзор: `list_folders()` (дерево со счётчиками); папка целиком: `get_folder({ path: "Программирование/Код" })`.
  Если в ответе есть `next_cursor`, передай его как `cursor` за следующей страницей.
- Проекты: `list_projects()`, `get_project({ name })`.
- Весь файл: ресурс `preferences://main`; ветка: `preferences://folder/{path}` (путь URL-кодированный).

Отвечай по сути и по папкам, с ограничениями в `моноширинном` виде. Технические `id` показывай, только если
просят.

## 3. Пользователь высказывает предпочтение — сохранить

Когда пользователь говорит о **долговременном** вкусе или правиле («не люблю…», «люблю, когда…», «запомни…»,
«всегда делай…», «терпеть не могу…»), вызови `add_preference`:

- `text` — фраза пользователя почти дословно, на его языке. Не переформулируй и ничего не добавляй: сервис сам
  разберёт полярность, папку, теги и ограничения и не должен получить того, чего пользователь не говорил.
- `project` — если правило явно про конкретный проект.
- Сообщи результат по полю «Результат»: *создано* (и в какой папке), *обновлено (конфликт)* — прежняя версия ушла
  в историю, *дубль* — такое уже было.

Не сохраняй разовые указания к текущей задаче («сделай этот файл короче», «переименуй функцию») — это не
предпочтения. Если непонятно, разовое это или навсегда, спроси. Если `add_preference` недоступен, запись в
сервисе выключена (`MCP_ALLOW_WRITE=false`) — скажи об этом и предложи добавить правило через веб-интерфейс.

## Промпт сервера

Если клиент показывает MCP-промпты, `apply_my_preferences` делает шаг 1 за тебя
(в Claude Code — `/mcp__preferences__apply_my_preferences`).

## Справка

- `references/tools.md` — параметры всех инструментов, формат ответа, примеры.
- `references/connect.md` — подключение сервера и установка навыка в Claude Code, Claude.ai/Desktop, ChatGPT,
  Codex, Cursor, VS Code/Copilot, Gemini CLI и других; решение проблем.
- `references/claude-md-rules.md` — правила «сначала предпочтения, потом реализация» для `CLAUDE.md`/`AGENTS.md`
  проекта; `scripts/setup-project.mjs` добавляет их в проект одной командой, `scripts/require-preferences.mjs` —
  хук Claude Code, который не даёт править файлы, пока предпочтения не загружены.
- `references/agent-instructions.md` — короткая версия для custom instructions и полей с лимитом символов.

Если пользователь просит подключить память предпочтений к проекту или агенту — используй эти файлы.
